# Full-matrix VM E2E — findings log

Running log for the two-VM matrix run (`cx-e2e-sup` supervisor mode, `cx-e2e-nosup` regular mode).
One row per defect found while the matrix runs: what failed, the evidence, where the fix landed.
Harness bugs and product bugs are labelled, because only one of the two ships to the fleet.

| # | Gate | Symptom (verbatim where possible) | Root cause | Kind | Fix / status |
| --- | --- | --- | --- | --- | --- |
| F7 | P2 shapes | `FAIL node-as-service is Running -> expected [Running], got [Stopped]`. The winsw wrapper log showed `Started 3292` and the error log `Error: Cannot find module 'pino' … code: 'MODULE_NOT_FOUND'`; running the app by hand in the guest reproduced it immediately | The Node app fixtures `require('pino')`, and the harness staged the app SOURCE but never their `node_modules`. `Dockerfile.nodeshapes` solves this by copying `nodeapp/node_modules` to the PARENT of the app directories (Node resolves upward, so one copy serves cjs/esm/mjs) — the VM path simply did not mirror it. Would have broken the PM2 shapes for the same reason. | harness | Fixed — the shared `node_modules` is staged to the same parent location the Dockerfile uses. The service itself was installed and started correctly, so the instrumenter under test was never implicated. |
| F6 | P1 staging | `[transport] recursive copy of …\otel-node reported failure; falling back to per-file` — and the per-file path was still grinding through a 71 MB tree of thousands of `node_modules` files with no end in sight | `guestcontrol copyto` copies file by file, and the trees this harness stages (otel-node, npm-global) are the worst possible shape for it. `--recursive` refused (it will not write into an existing target), so the fallback took over and turned staging into an hours-long step. | harness | Fixed — `Copy-DirToGuestAsZip`: compress on the host, one transfer, expand in the guest, with the per-file path kept as a fallback. Also removes the partial-copy failure mode where a tree lands a few files short and only fails later as a confusing "module not found" inside the guest. |
| F5 | P0 provision | Both runs failed `guestcontrol reaches the guest` after a 20-minute wait, and the VMs sat in `VMState="livesnapshotting"` with **no snapshot ever appearing** and no disk being written. Killing the client then left both machines registered as `<inaccessible>`, recoverable only by unregistering and re-cloning | P0 took its baseline snapshot with `snapshot take --live` on a running guest. On this host that state persists indefinitely, and while it persists `guestcontrol` stops answering - so the harness killed its own transport, then corrupted the machine XML when the interrupted operation was cut short. | harness | Fixed twice over: `New-VmSnapshot` now pauses, snapshots, and resumes instead of using `--live`, and P0 does not snapshot at all unless `-TakeSnapshot` is passed - the matrix never needed it. When it is passed, P0 additionally asserts the guest still answers afterwards, so this failure mode can never again be silent. |
| F4 | P1 prerequisites | Caught before it fired: the guest prerequisite report built `Node = (if (Test-Path …) { … } else { '' })` | In Windows PowerShell 5.1 the bare parenthesised `(if …)` **parses** — so a syntax check passes — and then fails at runtime with `The term 'if' is not recognized as the name of a cmdlet`, because it is read as a command invocation. The report would have said node was absent and failed a prerequisite that was actually satisfied. Only found by evaluating the form rather than parsing it. | harness | Fixed — `$(if …)` subexpression. The two in-flight runs were stopped and relaunched, because a PowerShell process has already loaded its script and cannot pick up the edit. |
| F3 | P0 transport | Both runs died after one assertion: `Cannot bind argument to parameter 'VmName' because it is an empty string`, and the summary printed `full-matrix (supervisor, )` with the VM name blank — despite `-VmName cx-e2e-c1` being passed | `VmLoop.Common.ps1` declared its transport state as `$script:VmName = $null`. Dot-sourcing runs in the CALLER's scope, so the shared file wiped the runner's own `-VmName` parameter before it was ever used. The same collision applied to `$User`, `$GuestStage` and friends. | harness | Fixed — all shared state is prefixed (`$script:VmlName`, `$script:VmlGcBase`, …), including the splat form `@script:GcBase`, which has no `$` and so survived the first rename pass. Verified with a probe script that dot-sources the file into a scope where `$VmName`/`$User` are already set. |
| F2 | pre-flight unit | `Merge-CxNodeOptions` returned `--require C:/cx/otel-node/register.js` **twice** when merging a value it had already written | The prior-hook check recognised our bootstrap only if its path matched `auto-instrumentations-node\|opentelemetry`. The default install prefix contains both by coincidence, so the bug is invisible there — but a vendored or differently-prefixed install (`-InstallPrefix C:\otel`) is not recognised, and every re-deploy appends another `--require`, loading the SDK twice. The function's own docstring promised this could not happen. | **product** | Fixed — recognition is now by exact normalised target (`file:///C:/x` = `C:\x` = `C:/x`), with the marker rule kept for values written by older versions, plus a new `-OwnedTargets` parameter so a caller can declare artifacts absent from the current bootstrap (an ESM→CommonJS switch would otherwise leave our stale `--experimental-loader` forever). Both callers updated. Pinned by 8 new assertions in `test/Test-ServiceInstrumenters.ps1`, incl. the app-keeps-its-own-`--require` false-positive case. |
| F1 | P0 provision | `Run-TestVM.ps1 -Action Unattended` died before doing anything: `Join-Path : Cannot bind argument to parameter 'Path' because it is an empty string` at line 35 (`$IsoPath` default) | `$PSScriptRoot` is **not populated while param-block defaults are evaluated**, so every default built from it (`$IsoPath`, `$PackagePath`, `$AdditionsIso`) collapsed to an empty path. The documented invocation `-Action Unattended` could never have worked without passing `-IsoPath` explicitly. The repo's other scripts already repair this after the param block; this one did not. | harness | Fixed — paths repaired after the param block, same `$here` pattern as `Install-CoralogixSupervisor.ps1` / `Run-SupervisorVmLoop.ps1`. |

## Notes on method

- A gate that passes after a fix but was never observed failing is not evidence: each row above
  records the failing observation first.
- Assertions are only loosened when the assertion itself was wrong, and then the reason is written
  in this table rather than left in the diff.
- Anything that turns out to be a genuine product limitation stays here as a known-open with its
  evidence instead of being quietly dropped from the matrix.
